## 0. Global structure and input model

- **Two screens**: `Screen::Login`, `Screen::Home`. Home has five **sections** (`Section` enum): `Home`, `Transactions`, `Accounts`, `Analytics`, `Settings`.
- **Shell layout** (Home screen): 1-row header (left 55%: section tabs `[Home] Transactions Accounts Analytics Settings`, with a breadcrumb ` > Categories` etc. when in Settings; right 45%: `Vault: <name> | User: <username>`), content area, 1-row bottom bar (left 75%: `[h] home [t] txn [a] accounts [y] analytics [s] settings │ <1-2 context hints> │ [?] help`; in visual mode instead `VISUAL (N selected) [Space] toggle [d] delete [c] categorize [Esc] exit`; right 25%: `⟳ HH:MM │ online/offline · <msg>`).
- **Event loop**: 200 ms tick, redraw each tick, spinner ticks, toast expiry checked each tick. Key handling is `async` and awaited inline, so the UI does not repaint while an HTTP call is in flight (no draw between `handle_key` start and end).
- **Key mapping** (`ui/keymap.rs`, `AppAction`): `Ctrl+C`→Quit, `Ctrl+P`→TogglePalette, `Ctrl+F`→Search, `Ctrl+R`→CycleAmbiguous, `Esc`→Cancel, `Tab`→NextField, `Enter`→Submit, `Backspace`, arrows, any other char→`Input(ch)`. There is **no Shift+Tab / BackTab mapping** (help overlay claims "Shift+Tab prev sub-tab" — it does nothing).
- **Dispatch priority** (`handlers/mod.rs`): 1) overlays (confirm → error → bulk-category → grouping → help → palette → global search), 2) global actions (Quit, Cancel, NextField, CycleAmbiguous), 3) login screen, 4) global toggles (palette, search), 5) section dispatch for Submit/Up/Down/Left/Right/Backspace, 6) `Input(ch)` → `route_input` (text fields) else `handle_non_login_key` (single-letter shortcuts).
- **Consequence**: when not inside a text field, `q` quits immediately (no confirmation). Letters typed into any focused text field are consumed as text.
- **Cancel (Esc) semantics** (`handlers/cancel.rs`): Login→quit; visual mode→exit visual; dirty txn/transfer form→"Unsaved Changes" dialog; active list search→deactivate search (query is *kept*); recurring sub-mode→back to list/exit; then per-mode back-navigation; at top level of a section→go Home.
- **Loading overlay**: fullscreen braille spinner `⠋⠙⠹…` with "Loading... / Fetching vault data" whenever `snapshot` is None on Home and no error dialog.

## 1. Screens / views

### 1.1 Login (`ui/screens/login.rs`, `actions/login.rs`)
- Centered 32×6 box titled "login", two unlabeled inputs (username prefilled from config, password masked with `•`), focus cursor `│`. `Tab` toggles field, `Enter` submits, `Esc` quits.
- Vault is NOT chosen on screen; comes from config (`vault` key). Requires username, password and a vault id or name, else "Fill all fields."
- Flow: set basic-auth credentials → `POST vault/get` → `POST vault/snapshot`; on snapshot **404** falls back to `POST flows/shared` and builds a synthetic snapshot with zero wallets (shared-only user). Then applies local defaults, loads transactions page 1 and stats.
- Error message rendered below the box (mapped via `login_message_for_error`).

### 1.2 Home / Dashboard (`ui/screens/home/*`)
Responsive: width ≥100 → stats bar (3 cards, 6 rows) + `Balances` (30%) | `Activity Feed` (70%); 80–99 → stacked; <80 → one-line compact stats `Net Worth: X │ In: Y │ Out: Z`.
- **Net Worth card**: sum of non-archived wallet balances (client-side); a `▲ +x.x%` line computed as `(income − expenses) / expenses × 100` for the current month (odd metric); braille area sparkline of 30-day cumulative net.
- **Income / Expenses cards**: current calendar month totals (client-computed, see §5), "this month" subtitle.
- **Balances card**: `Wallets` (non-archived, sorted by balance desc, count limited by height) and `Budgets` (non-archived, non-unallocated flows, snapshot order). Amount colored green ≥0, red <0.
- **Activity Feed**: list of `HomeFeedItem`s = flow alerts first, then transactions of the *currently loaded transactions page*. Alerts: `Critical` if flow balance < 0 (label "deficit"), `Warning` if `0 ≤ balance ≤ low_balance_minor` (label `≤ <threshold>`); sorted severity → balance asc → name; unallocated/archived flows excluded. Transactions grouped by date header (`Today` / `Yesterday` / `%A, %d %b` / `%d %b %Y`). A one-line **insight** is inserted after the first date header: `💡 Insight: You saved X (p% of income) this month` or `Expenses exceed income by X this month`. Row: kind icon (`▲ ▼ ↩ ⇄`), optional money emoji (`💰`/`💸` if emoji_mode), signed amount right-aligned 14 cols, `HH:MM` (if width ≥50), note truncated, `🏷category` (if width ≥70).
- Keys: `↑/↓` or `j/k` move; `Enter` opens transaction detail (jumps to Transactions) or flow detail (jumps to Accounts>Budget); `n` → Transactions with quick-add active; `N` → Transactions + New Expense modal; `h/t/a/y/s` navigation.

## 2. Transaction entry UX

### 2.1 Modal form (`TransactionFormState`, `actions/transactions_submit/form.rs`, `ui/screens/transactions/form.rs`)
- Opened via `N` (Expense), `i` (Income), `R` (Refund), palette, or `e` in detail (edit). Title `New/Edit Income|Expense|Refund`.
- `TransactionFormState { kind, amount: AmountField, wallet_index, flow_index, category: TextField, note: TextField, occurred_at: DateField, focus, error, category_index, editing_id }`.
- Fields in Tab order (`TransactionFormField`): `Amount` → `Wallet` → `Flow` → `Category` → `Note` → `OccurredAt` → (wraps). Rendered as `Label     [value▏]  ← helper` with helpers: "Enter numerical amount (required)", "Source/destination wallet", "Envelope/budget allocation", "Tag for analytics", "Optional description", "Date & time (default: now)". Below: two picker lists (Wallets | Flows, ordered default→recent→rest, highlight follows focus), "Recent categories" list (`#cat`, up to 5), and a recents footer `Recents: Categories: #a #b #c • Wallet: x, y • Flow: z`. Hints `[Enter] Save [Esc] Cancel [Tab] Next field [↑↓] Cycle choices`.
- `↑/↓` on Wallet/Flow cycles the index through the ordered active list (wrap); on Category cycles `recent_categories` and writes the name into the field; typing in Category resets `category_index`.
- Defaults on open: `occurred_at` = now formatted `%Y-%m-%d %H:%M` in app tz; wallet/flow index from `default_transaction_form_indices`: if a scope wallet/flow is set use the `default_wallet_flow` resolution, else first *recent* id present in the ordered list, else the resolved default.
- **Validation on submit** (order): amount non-empty ("Amount required") → `Money::parse_major` (accepts `.` or `,` decimal, optional leading `+`/`-`, max 2 decimals, digits only; the sign is discarded via `.abs()`) → `> 0` → wallet list non-empty ("No wallet available.") → flow list non-empty (else "Unallocated flow missing.") → `occurred_at` if non-empty must parse **strictly** as `%Y-%m-%d %H:%M` in the configured tz (ambiguous DST → first, non-existent → "Invalid timezone"). Category: leading `#` stripped, empty → `None` on create / `Some("")` on edit. Note same. Transfer kinds are rejected here ("Use the dedicated transfer form.").
- Live `AmountField` validator (`validation/amount.rs`) is *more permissive/different* from submit: it accepts `1.234,56`, `1,234.56`, single separator always decimal, truncates >2 decimals — but the submit path uses `Money::parse_major`, which rejects >2 decimals and thousands separators. `DateField` likewise accepts `YYYY-MM-DD`, `YYYY-MM-DD HH:MM`, `DD/MM/YYYY[ HH:MM]`, `DD-MM-YYYY[ HH:MM]` for the ✓/✗ indicator, but submit only accepts ISO with time. Inconsistency.
- Create → `POST income|expense|refund` (`category_id: None`, category by name, `idempotency_key: None`), sets `last_flow_id`, `last_created_id`, toast "Transaction saved.", then reload page 1 + snapshot + stats.
- Edit → `PATCH transactions/{id}` with `amount_minor, wallet_id, flow_id, category, note, occurred_at(optional)`; voided txns cannot be edited ("Voided transaction: editing not available."); if the txn's wallet/flow is archived (not in active ordered list) → toast "Archived wallet/flow: editing not available." After edit, detail is re-opened.
- Dirty check for the discard dialog: `editing_id.is_some() || amount || category || note non-empty`. Dialog: `[Enter] Save`, `[d] Discard`, `[Esc]` cancel.

### 2.2 Quick add (`src/quick_add.rs`, `actions/transactions_submit/quick_add.rs`, `ui/screens/transactions/quick_add.rs`)
Inline bar at top of the list, `n` activates, `Enter` submits, `Esc` clears. Placeholder "Press [n] to add transaction...". Collapsed hints: `⚡ Syntax: [+]amount note [#category] [@wallet] [>envelope]`, `Examples: 50 lunch #food @main | +100 salary >income | r30 refund`, `[n] quick add [i] income [e] expense [t] transfer [?] help` (note: `e` and `t` hints are wrong; `e` does nothing in list, `t` navigates to Transactions; expense modal is `N`, transfer is `T`). Active hint: `Syntax: [+]amount note [#cat] [@wallet] [>envelope]  |  + income, r refund`.

Parser rules (literal from code):
```
trimmed = input.trim(); empty → "Enter an amount."
if strip_prefix("tw>") or "TW>"  → parse_transfer_wallet(rest.trim_start())
if strip_prefix("tf>") or "TF>"  → parse_transfer_flow(rest.trim_start())
kind: strip_prefix('r') | 'R' → Refund; '+' → Income; '-' → Expense; else Expense
      (the char after the prefix is trim_start'ed, so "r 30" and "r30" both work)
parts = rest.splitn(2, ' '); amount_raw = parts[0].trim()   (empty → "Amount missing.")
amount = Money::parse_major(amount_raw, currency).minor().abs()
      (err → "Invalid amount."; == 0 → "Amount must be > 0.")
note_raw = parts[1].trim(); tokens = note_raw.split_whitespace():
  "#x" → category = lowercase(x)   (second "#x" → "Too many tags: maximum 1.")
  "@x" → wallet   = lowercase(x)   (second → "Too many wallets: maximum 1.")
  ">x" → flow     = lowercase(x)   (second → "Too many envelopes: maximum 1.")
  bare "#", "@", ">" are kept as note words
  everything else joined with ' ' → note (None if empty)
transfers: amount as above; targets = tokens with prefix '@' (tw) or '>' (tf), lowercased,
           in order of appearance; must be exactly 2 → from, to
           ("Specify exactly 2 wallets (@from @to)." / "Specify exactly 2 flows (>from >to).");
           remaining tokens → note
```
`QuickAddKind::{Income, Expense, Refund, TransferWallet, TransferFlow}`; `QuickAddParsed { kind, amount_minor, category, wallet, flow, note, from_wallet, to_wallet, from_flow, to_flow }`.

Notes: because the kind is detected by `strip_prefix('r')`, any input starting with the letter r (e.g. `rent 50`) is a refund and then fails on amount. Amount must be the **first token**, no currency symbol, no thousands separator. **No date tokens**; `occurred_at` is always `now` (preview shows "Today"). Category is sent as a *name string* (server resolves/creates; aliases presumably server-side — unsure).
- **Resolution** (`resolve_quick_add_targets`): baseline = `default_wallet_flow` (§2.4); wallet/flow overrides resolved case-insensitively against *active* entities ordered default→recent→rest, priority exact > prefix > contains (`resolve_wallet_name` / `resolve_flow_name`, returns `(id, name, is_exact)`); not found → `Wallet not found: @x` / `Envelope not found: >x` (transfers: `Flow not found: >x`). Category: if an ambiguous selection exists use its name, else pass the typed string through.
- **Live preview line**: `▼ 15.00 EUR  pizza  │  #food  │  >groceries  │  @cash  │  Today` (transfer: `@bank → @cash`); unresolved shows `?@x` in warning color; single match shows `@Name` in accent; defaults shown muted (`@<default wallet>`, `><default flow>`). Envelope suggestions line (`Envelope suggestions: a, b, c`, up to 3, via `flow_name_suggestions`) when the `>query` is not an exact match.
- **Ambiguity** (`QuickAddAmbiguous { kind: QuickAddAmbiguousKind::{Category, Wallet, Flow}, options: Vec<(Uuid, String)>, selected }`): when >1 match, a line `#? food | grocery | restaurant  [Ctrl+R] cycle` appears (up to 3 names per kind); `Ctrl+R` initializes/cycles the first ambiguous kind in priority category → wallet → flow; selected option shown `[name]` and used on submit.
- Success clears input, sets `last_flow_id`, `last_created_id`, toast "Transaction saved." / "Wallet transfer saved." / "Flow transfer saved."; error shown as `⚠ msg` under the input.

### 2.3 Repeat (`r` in Detail)
Builds a fresh create payload from `TransactionDetailResponse` (`RepeatPayload::{Income, Expense, Refund, TransferWallet, TransferFlow}`): same `amount_minor`, `category_id: Some(detail.category_id)` + `category`, `note`, wallet/flow ids extracted from legs (`extract_wallet_flow`: last Wallet leg / last Flow leg; transfers via `extract_wallet_transfer`/`extract_flow_transfer`: negative leg = from, positive = to, error "Cannot determine transfer wallets/flows."), `occurred_at = now`. Toast "Transaction repeated." Also updates `last_flow_id` for non-transfers.

### 2.4 Defaults & recents
- **Local defaults file** `config/tui_state.json` (`LocalState { defaults: [DefaultsEntry { username, vault_id, default_wallet_id, default_flow_id }], command_history: [CommandHistoryEntry { username, vault_id, recent_commands }] }`), keyed per (username, vault). Set in Settings > Vault > `d` (`DefaultsFormState { wallet_index, flow_index, focus: DefaultsField::{Wallet, Flow}, error }`, index 0 = "None"). Invalid/archived ids are dropped on each snapshot (`normalize_defaults`). Toast "Defaults saved."
- **Default wallet/flow resolution** (`resolve/defaults.rs`, literal doc-comment priority): wallet: 1 scope wallet (`transactions.scope_wallet_id`), 2 default wallet, 3 first recent wallet, 4 first active wallet; flow: 1 scope flow, 2 default flow, 3 first recent flow, 4 `last_flow_id`, 5 unallocated flow. All must be non-archived. Fallback names `"-"` (wallet) and hardcoded Italian `"Non in flow"` (flow). Errors: "Snapshot unavailable.", "No wallet available.", "Unallocated flow missing."
- **Ordering of pickers** (`ordered_ids(active, recents)`): `[default id] + recent ids` (deduped, only if active) then remaining active ids in snapshot order.
- **Recents**: `recent_categories` (up to 5, first-seen from the loaded page, case-insensitive dedupe; on a page-1 reload also refreshed from a 90-day window query, limit 50, kinds Income/Expense/Refund only, excluding voided, respecting current scope), `recent_wallet_ids`/`recent_flow_ids` (up to 5 from the same query, order of appearance, `push_recent_id` ignores duplicates and stops at limit). `last_flow_id` = last flow used on create/edit/picker/repeat, validated against snapshot on every snapshot (`ensure_last_flow`), else unallocated.

### 2.5 Date/time conventions
- App timezone from config (`timezone`, IANA; invalid → UTC). `now_in_timezone()` = UTC now localized then converted to a fixed offset for the API.
- Input format for When/filters: exactly `YYYY-MM-DD HH:MM` (local, `parse_local_datetime`). No relative dates ("yesterday", "-3d") anywhere.
- Display: list `HH:MM` (+ `dd Mon` when not grouped by date), detail `dd Mon YYYY HH:MM`, recent panels `dd Mon HH:MM`, global search `YYYY-MM-DD`, filter summary `YYYY-MM-DD`; formatted directly from the server's `DateTime<FixedOffset>` (i.e., in whatever offset the server returned, not re-localized — only edit prefill uses `format_local_datetime`). Date group headers `Today`/`Yesterday` computed with `chrono::Local` (system tz, not config tz).

## 3. Transfers
- `TransferType { Wallet, Flow }` (`actions/transfer_common.rs`). Shared helpers: `validate_transfer_amount` (parse_major, abs, >0), `validate_different_ids`, `validate_minimum_count` (≥2 active items).
- Entry: `T` → picker (Wallet transfer / Flow transfer, `↑/↓` toggles, Enter) → `TransferFormState { from_index, to_index, amount: AmountField, note: TextField, occurred_at: DateField, focus: TransferField, error, editing_id }`. Fields `From → To → Amount → Note → OccurredAt` (Tab, wraps). `↑/↓` cycles From/To over **active** wallets/flows in snapshot order (not MRU-ordered). Defaults from=0, to=1 (0 if only one). Right panel "Available" lists items with ` [from]` / ` [to]` markers. Hint line `Tab: next • ↑/↓: change • Enter: save • Esc: cancel`. Title "Transfer Wallet"/"Transfer Flow"/"Edit Transfer Wallet"/"Edit Transfer Flow".

## 4. Listing, filters, search, pagination
- **Server query** (`TransactionList`): `vault_id, flow_id (scope), wallet_id (scope), limit: 20, cursor, from, to, kinds: Option<Vec<TransactionKind>>, include_voided (default false), include_transfers (default true)`. Wallet scope and flow scope are mutually exclusive (setting one clears the other). For shared-only users the scope is forced to the first shared flow (`ensure_flow_scope_for_shared`).
- **Pagination**: cursor-based; `]` loads `next_cursor` (pushes previous cursor onto `prev_cursors` stack), `[` pops. Any reload (`r`, mutation, filter change, vault switch) resets to page 1 (`TransactionsState::reset()` also clears search, visual selection, detail, quick-add, forms, recents lists, `last_created_id`, `recurring_mode`). No infinite scroll, no page indicator, no sort control (server order).
- **Filter dialog** (`/`, `TransactionsFilterState { from_input, to_input, focus: FilterField::{From, To, Kinds, Transfers}, error, kind_income, kind_expense, kind_refund, kind_transfer_wallet, kind_transfer_flow, include_transfers }`): fields `From`, `To` (text, `YYYY-MM-DD HH:MM`, prefilled from current filter), `Transaction Types (press key to toggle)` rendered as `[✓] ▲ Income (i)  [✗] ▼ Expense (e)  [✗] ↩ Refund (r)` / `[✗] ⇄ Wallet Transfer (w)  [✗] ⇄ Flow Transfer (f)` toggled by letter when Kinds focused, `Show Transfers [On]/[Off] (t to toggle)` (`t` or Space when Transfers focused). `Tab` cycles From→To→Kinds→Transfers. `Enter` applies (empty kinds = `None` = all), `Esc` cancels. `c` in list clears filters **and** scope (`clear_filters`).
- **In-list text search** (`ListSearchState { query, active }`, shared by transactions, wallets, flows, recurring state; `Ctrl+F` starts): client-side over the loaded page only. `transaction_matches_query(tx, normalized_query)` matches lowercase substring against, in order: kind label (`income|expense|refund|transfer wallet|transfer flow`), note, category, `abs(amount_minor).to_string()` (minor units, e.g. "1500" for 15.00), and `occurred_at.format("%Y-%m-%d %H:%M")`. Wallet/flow lists match `name.to_lowercase().contains(query)` and also respect `show_archived`. Esc deactivates typing but the query stays applied (footer says "[Esc] clear" — only vault switch / home-feed open / list reset actually clear it). Selection is clamped to visible items (`refresh_*_search`); in Detail mode the detail is re-fetched for the new selection. Empty-result message `No results for "q"` + `Ctrl+F to edit • Esc to clear`.
- **Grouping** (`GroupingMode::{Date, Category, Wallet, Envelope}`, cyclic): groups in first-seen order keyed by `YYYY-MM-DD` / category name (else "Uncategorized") / `wallet:<id>` ("No wallet") / `flow:<id>` ("No envelope"); header `Category: X` etc. (Date: date label), total = Σ `signed_amount_minor` (expense negated, everything else as-is). Keys: `d/c/w/e`, `1-4`, arrows, Enter. Selection clamped after regrouping.
- **Visual mode** (`v`, `visual_mode: bool`, `visual_selected: BTreeSet<Uuid>`): multi-select with `Space`, markers `*`; `d` → "Delete N transactions?" confirm with hint "You can undo this action for 5 seconds."; `c` → Bulk Categorize input dialog (`#` stripped, empty → "Enter a category.") → N × `PATCH transactions/{id} { category }`, toast `Categorized N transactions as #cat` (+ error toast `msg (fails/total)`); `Esc` exits. Entering visual mode closes quick add.
- **Delete = void with undo**: ids go to `pending_delete_ids` (hidden immediately, selection clamped, detail closed), undo toast `Deleted "note" (amount)` (label "Transaction" if no note) / `Deleted N transactions`; on `u` restores visibility ("Undo applied."); on expiry (or before the next destructive action via `finalize_pending_undo`, which is called before queueing another delete, archiving a wallet/flow, or bulk categorizing) performs `POST transactions/{id}/void` for each id, then refreshes. Failures reported as `msg (fails/total)`. `z` toggles `include_voided`. `v` in Detail voids immediately with toast "Transaction voided.", no undo.

## 10. Client layer (`src/client/*`)
- `Client { base_url: Url, http: reqwest::Client (default settings, no timeout), credentials: Option<(user, pass)> }`; **HTTP Basic auth** on every request (`set_credentials` at login); credentials only in memory (never written; the password is never read from CLI/env/config). Endpoints are joined onto `base_url` with `Url::join` (a missing trailing slash on a base path would drop the last segment).
- Endpoints used: `POST vault/get`, `POST vault/snapshot`, `POST vault/list`, `POST vault/new`, `DELETE vault/{id}`, `POST wallets`, `PATCH wallets/{id}`, `POST flows`, `PATCH flows/{id}`, `POST flows/shared`, `POST cashFlow/get`, `DELETE vault/{id}/flow-references/{flow}`, `POST transactions` (list), `POST transactions/get`, `POST transactions/{id}/void`, `PATCH transactions/{id}`, `POST income`, `POST expense`, `POST refund`, `POST transferWallet`, `POST transferFlow`, `POST categories/list`, `POST categories`, `PATCH categories/{id}`, `POST categories/{id}/aliases/list`, `POST categories/{id}/aliases`, `DELETE categories/{id}/aliases/{alias}` (with JSON body), `POST categories/{id}/merge/preview`, `POST categories/{id}/merge`, `GET vault/{id}/members`, `POST vault/{id}/members`, `DELETE vault/{id}/members/{user}`, `GET/POST vault/{id}/flows/{flow}/members`, `DELETE vault/{id}/flows/{flow}/members/{user}`, `POST recurring/list`, `POST recurring/pending`, `POST recurring`, `PATCH recurring/{id}`, `POST recurring/{id}/archive`, `POST recurring/{id}/execute`, `POST stats/get`.
- **Error mapping** (`ClientError::{Unauthorized, Forbidden(p), NotFound(p), Conflict(p), Validation(p), BadRequest(p), Server(p), Client(String), Transport(reqwest::Error)}`): 401 → `Unauthorized` (body ignored); otherwise body `ErrorEnvelope { error: ErrorPayload { code, message, details } }` parsed (fallback `ErrorCode::Unknown` / "unknown error"); 403 `Forbidden`, 404 `NotFound`, 409 `Conflict`, 422 `Validation`, 400 `BadRequest`, else `Server`; transport → `Transport`. `login_message_for_error` localizes: Unauthorized → "Invalid credentials or missing pairing."; Forbidden by code (membership codes above, else "Operation not permitted."); NotFound code `NotFound` → "Resource not found." else raw message; Conflict → "Conflict: {message}"; Validation containing `"ambiguous vault name"` → "Vault name is ambiguous. Use \"Main (owner)\" or a vault id." else "Validation error: {message}"; BadRequest → "Bad request: {message}"; Server → "Server error: {message}"; Transport → "Server unreachable: {error}".
- Two helper paths: `on_api_error_connection` (data loads: sets offline + returns message for a screen error field) and `on_api_error_toast` (mutations: error toast with a fixed key + returns message for the form error field).
- No retries, no caching, no request cancellation/debounce, no idempotency keys (`idempotency_key: None` always), no optimistic updates except the delete-undo hide. Every mutation triggers `refresh_after_transaction_mutation`: reload transactions page 1 (+ recents query) + snapshot (+ wallets/flows search refresh) + stats (+ 180-day history fetch), which is heavy. Wallet/flow/category/member mutations refresh the snapshot (which also reloads stats).
- **Local state**: `config/tui_state.json` (path relative to CWD, `default_state_path()`), pretty JSON, for defaults and palette MRU; best-effort save (errors on MRU save ignored; on defaults save shown as error).

Version flag disabled.

## 14. Warts / inconsistencies observed
No `TODO`/`FIXME`/`XXX`/`HACK` comments exist in the crate. Observed from code:
- `q` quits instantly from any list view (and `Ctrl+C`), no confirmation; `x` in Vault view opens the delete-vault dialog next to `c`/`d`.
- Help overlay and quick-add hint bar advertise keys that do not exist or differ (`Shift+Tab`, `Tab` for sub-tabs, `[e] expense`, `[t] transfer`; help says `1/2/3` for settings but `4` also exists).
- Live field validators (`AmountField`/`DateField`) accept formats the submit path rejects (thousands separators, `DD/MM/YYYY`, date without time); `AmountField` required error is Italian in both locales.
- Quick-add: leading `r` means refund, so notes starting with "r" cannot be first; amount must be the first token; no date token; category typos silently create new categories unless the ambiguity UI appears; `occurred_at` always now.
- Search query persists after Esc despite "[Esc] clear" hint; `reset()` on every reload wipes recents until re-fetched; search/global search only cover the loaded page (20 rows).
- Every mutation refetches transactions, snapshot, stats and 180 days of history (paged 200); UI is frozen during awaits (no repaint, spinner does not animate mid-request).
- Stats MoM always compares the latest two months, ignoring the selected month; "Net Worth" tab has no net-worth history; home net-worth "% change" formula is net/expenses; month navigation beyond the 180-day window shows zeros; `Local::now()` (system tz) vs config tz mixing; transaction times displayed in the server's offset.
- Flow mode/cap/allow_negative are immutable after creation in the UI; flow cap badge hardcodes "EUR" and dot formatting; transfer From/To lists are snapshot-ordered while other pickers are MRU-ordered.
- Recurring: `f64` amount parsing (Create-mode parse failure aborts the handler with an `AppError`), unvalidated dates, wallet/flow pickers include archived entities, category lost on edit, no "skip" for pending items, Backspace not routed in Edit mode.
- Wallet-scope and flow-scope filters are mutually exclusive; `v` in detail voids without confirmation while `d` has undo; member removal has no confirmation.
- Preferences (emoji, density) not persisted; density is a no-op.
- Vault delete message and a few strings are hardcoded Italian; many UI strings hardcoded English; single currency (EUR) throughout; only one theme; month names English.
- Global search finds categories only if the Categories tab was visited (items loaded lazily).
- Login has no vault picker; vault comes from config; ambiguous vault names must be fixed in config.
- `Density`, `search` on `RecurringState`, and `FieldState`/`LengthValidator` empty impls are dead or unused code paths.
